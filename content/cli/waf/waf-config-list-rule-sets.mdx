---
title: Listar catálogo de reglas WAF disponibles
description: Muestra los conjuntos de reglas WAF que ofrece Azure, con sus grupos y los IDs de cada regla.
shell: azurecli
category: WAF
tags: [waf, owasp, crs, catalogo, reglas, application-gateway, consulta]
template: "az network application-gateway waf-config list-rule-sets --type <ruleSetType> --version <version> --group '<group>' --output <output>"
parameters:
  - name: ruleSetType
    label: Tipo de conjunto
    type: enum
    required: true
    default: OWASP
    options: [OWASP, Microsoft_DefaultRuleSet, Microsoft_BotManagerRuleSet]
  - name: version
    label: Versión del conjunto
    description: "3.2 para OWASP, 2.1 para Microsoft_DefaultRuleSet, 1.1 para el de bots."
    type: string
    required: true
    default: "3.2"
    placeholder: "3.2"
  - name: group
    label: Grupo de reglas
    description: Un nombre de grupo concreto, o * para todos los grupos con sus reglas.
    type: string
    required: true
    default: "*"
    placeholder: REQUEST-942-APPLICATION-ATTACK-SQLI
  - name: output
    label: Formato de salida
    type: enum
    required: false
    default: table
    options: [table, json, jsonc, tsv, yaml]
---

Este es el catálogo de Azure, no la configuración de tu política: devuelve qué reglas existen en cada conjunto y su ID, independientemente de lo que tengas aplicado.

Es la pieza que falta para auditar de verdad. Como `managed-rule rule-set list` solo devuelve las reglas modificadas, el estado real de cada regla sale de cruzar las dos salidas: lo que no aparece como override está activo con su acción por defecto.

El asterisco va entre comillas a propósito: sin ellas el shell lo expandiría a los nombres de archivo del directorio actual. Si lo omites (borrando el flag) solo lista los grupos, sin bajar al detalle de las reglas.
