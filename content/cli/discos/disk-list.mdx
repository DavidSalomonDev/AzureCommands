---
title: Listar discos de un grupo de recursos
description: Discos administrados de un grupo, filtrados por tipo de disco, sin necesidad de Resource Graph.
shell: azurecli
category: Discos
tags: [disco, disk, listar, filtrar, tipo, sku, hdd, ssd, premium, consulta]
template: "az disk list --resource-group <resourceGroup> --query \"[?starts_with(sku.name, '<tipoDisco>')].{Nombre:name, Tipo:sku.name, GB:diskSizeGB, Estado:diskState, VM:managedBy}\" --output <output>"
parameters:
  - name: resourceGroup
    label: Grupo de recursos
    type: string
    required: true
    placeholder: mi-grupo-recursos
  - name: tipoDisco
    label: Tipo de disco
    description: Prefijo del SKU; Standard_LRS es HDD, StandardSSD es SSD estándar, Premium incluye Premium_LRS, Premium_ZRS y PremiumV2_LRS.
    type: enum
    required: true
    default: Standard_LRS
    options: [Standard_LRS, StandardSSD, Premium, UltraSSD]
  - name: output
    label: Formato de salida
    type: enum
    required: false
    default: table
    options: [table, json, jsonc, tsv, yaml]
---

La alternativa cuando no tienes la extensión de Resource Graph o solo te interesa un grupo. Trabaja sobre la suscripción activa: borra `--resource-group` para recorrer la suscripción completa.

El filtro por tipo se hace en cliente con `--query`, así que el `starts_with` se comporta igual que en la consulta del tenant: `Standard_LRS` son HDD, `StandardSSD` los SSD estándar, `Premium` cubre `Premium_LRS`, `Premium_ZRS` y `PremiumV2_LRS`, y `UltraSSD` los Ultra Disk. Para ver todos los discos sin filtrar, quita el `[?starts_with(...)]` y deja `[].{...}`.

La columna `VM` es el id completo del recurso que tiene el disco tomado, y aparece vacía en los discos sin conectar. Si solo quieres esos, cambia el filtro por `[?diskState=='Unattached']`.
